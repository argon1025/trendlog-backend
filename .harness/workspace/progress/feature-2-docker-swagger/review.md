# 워크스루 리뷰 기록

## 리뷰 1차 2026-07-19

리뷰 시점의 브랜치에는 플랜 스냅샷 커밋 하나만 있었어요. 그래서 "무엇을 왜 만들 것인가" 기준으로 계획을 다섯 단위로 나눠 훑었어요. 순서는 MySQL 컨테이너 → dev/prod 프로파일 분리 → Testcontainers 테스트 복구 → Swagger 도입과 REST Docs 제거 → VS Code 실행 구성이에요. 마지막에 새 개발자가 저장소를 처음 받았을 때의 전체 흐름을 한 번 이어서 확인했어요.

---

### 지적 1 — 로컬 MySQL 호스트 포트를 3310으로

- **지적:** 다른 사이드 프로젝트가 돌고 있으니 기동 포트를 3306이 아닌 3310으로 바꿔야 해요.
- **수용 여부:** 수용
- **사유:** 사용자 개발 머신에서 호스트 3306은 이미 다른 프로젝트가 점유하고 있어요. 계획대로 `3306:3306`을 쓰면 `docker compose up -d`가 포트 충돌로 실패해요. 원래 값은 다른 프로젝트의 존재를 모르는 상태에서 정한 것이라, 계획의 설계 의도를 해치지 않고 바꿀 수 있어요. 컨테이너 내부 포트는 3306으로 두는 쪽을 골랐어요. 내부까지 바꾸면 MySQL 설정 파일을 따로 손대야 하는데 얻는 게 없어요.
- **변경 결과:** 기존에는 `compose.yaml` 포트 매핑이 `3306:3306`이고 `application-dev.yaml` 접속 URL이 `localhost:3306`이었어요. plan.md의 `## Re-plan 2026-07-19` 섹션에서 매핑을 `3310:3306`으로, 접속 URL을 `localhost:3310`으로 정정하고 전체 검증 절차의 포트 확인 방법도 함께 고쳤어요. 커밋 3의 Testcontainers는 실행할 때마다 임의 포트를 잡으므로 변경 대상이 아니라는 점을 명시했어요.

### 남은 한계 (리뷰 중 공유, 이번 범위 밖으로 합의)

- `./mvnw test`가 Docker 데몬을 요구해요. Docker를 못 쓰는 CI 환경이면 테스트 전략을 다시 짜야 해요.
- `ddl-auto: update`는 컬럼 삭제나 이름 변경을 따라가지 못해요. 스키마 마이그레이션 도구 도입은 뒤로 미뤘어요.
- 접속정보가 `.env`와 `application-dev.yaml`에 두 벌 있어요. 접속 대상을 설정 파일에서 바로 보이게 하려고 감수한 중복이에요.
- prod 설정이 데이터소스만 다뤄요. 로깅 수준, 커넥션 풀 크기, 서버 포트는 기본값이에요.
- `OpenApiConfig`에 인증 스킴 정의가 없어요. 로그인이 붙는 시점에 추가해야 해요.
